# Hospital BI
Sample project for Urban Level 1 Trauma Center

<h1>Hospital BI SQL Pack (v0.1)</h1> <h2>Context</h2> <h3>Purpose</h3> <p>A small, synthetic hospital dataset and SQL query pack to demonstrate BI/analytics skills for hospital operations.</p> <h3>Organization flavor</h3> <p>Modeled on publicly available information about a private urban Level 1 Trauma Center: Level 1 Trauma Center, safety‑net payer mix, ~60k ED visits/year, teaching hospital.</p> <h3>Data ethics</h3> <p>Fully synthetic; no PHI.</p> <h2>Data Model (CSV in /data)</h2> <p><strong>admissions.csv</strong><br> admission_id, patient_id, admit_dt, discharge_dt, admit_src, discharge_disp, payer, ed_flag, ward, race_ethnicity, trauma_flag</p> <p><strong>diag.csv</strong><br> encounter_id, admission_id, icd10, primary_flag</p> <p><strong>ed_visits.csv</strong><br> visit_id, patient_id, arrival_ts, triage_level, door_to_doc_min, dispo, stroke_alert, stemi_alert, language</p> <p><strong>providers.csv</strong><br> provider_id, dept, specialty, npi</p> <h2>Relationships</h2> <p>admissions 1–* diag (via admission_id)<br> ed_visits is independent (no direct FK to admissions in v0.1)<br> providers is a small reference table (not joined in v0.1 KPIs)</p> <h2>Tech Stack</h2> <p><strong>Engine:</strong> SQLite (tested with DB Browser for SQLite). Can be ported to SQL Server with minor syntax edits.<br> <strong>Optional visualization:</strong> Excel/Power Query or Power BI for a one‑page KPI mock.</p> <h2>Setup</h2> <p>1) Create hospital.db in the project root.<br> 2) Run /sql/01_create_tables.sql.<br> 3) Import CSVs from /data into matching tables.<br> 4) Open /sql/10_queries.sql and run queries 01–10.</p> <h2>KPIs (queries in /sql/10_queries.sql)</h2> <p>01. Admissions by day/week — volume trend for capacity planning.<br> 02. Average Length of Stay (LOS) — excludes active admissions.<br> 03. 30‑day readmissions (all‑cause) — subset by payer as needed.<br> 04. Top primary diagnoses — case mix overview.<br> 05. Discharge disposition mix — post‑acute flow/mortality proxy.<br> 06. ED LWBS rate — access/throughput pressure.<br> 07. ED Door‑to‑Doc avg and P90 (approx) — timeliness/bottlenecks.<br> 08. Payer mix distribution — safety‑net profile/revenue planning.<br> 09. Equity slice: Door‑to‑Doc by ward or race_ethnicity (aggregate).<br> 10. KPI assemble — single‑row combined signals.</p> <h2>Validation Checklist</h2> <p>Row counts; LOS spot checks; readmission logic; null handling; ED sanity.</p> <h2>Assumptions & Limitations</h2> <p>Synthetic distributions; no ED→inpatient join (ed_flag approximates origin); percentiles approximated in SQLite.</p> <h2>Project Structure</h2> <p>/data, /sql, /artifacts (optional), README.md, validation_checklist.md</p> <h2>Power BI Mock (optional)</h2> <p>Single page 16:9 (1280×720) at 100% zoom; Date (Between) and Dispo slicers; four KPI cards; Payer Mix matrix; Admissions trend line.</p> <h2>Interview Prompt</h2> <p>“I built a small, hospital‑flavored synthetic dataset … and wrote 10 SQL queries … plus a validation checklist and a simple Power BI mock.”</p> <h2>Sources</h2> <p>HUH About & Emergency pages; AHA Metropolitan Anchor Hospital case study.</p> <h2>License</h2> <p>MIT for code/queries; data is fictional and free to use.</p>
